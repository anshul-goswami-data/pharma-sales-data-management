# Pharma Sales Data Management Pipeline

An end-to-end **data management and BI project**: messy monthly sales files from three distributors are profiled, cleaned, matched to a hospital master, validated with data-quality rules, modelled in SQL Server, and shown in a Power BI dashboard.

> All data is **synthetic** (generated by `src/generate_data.py`). No real company, hospital or patient data is used.

## Business problem
A pharma company in Japan receives monthly sell-out data from three distributors. Each distributor:
- uses **different column names and date formats**
- writes **hospital names differently** (abbreviations, upper case, extra spaces, typos)
- sends **duplicate rows**, **missing product codes**, returns as **negative quantities**, and sometimes **unknown hospitals**

Management needs a **trusted monthly KPI dashboard by the 5th of each month**.

## Architecture
```
data/raw/            Distributor CSVs (messy)          -> "Bronze"
   │  Python: profile, standardize, deduplicate, match to master
data/processed/      Clean, conformed sales            -> "Silver"
   │  SQL Server: star schema + data-quality tables
SQL Server mart      fact_sales, dim_hospital, ...     -> "Gold"
   │
Power BI             Sales KPIs + Data Quality scorecard
```

## Repository layout
| Path | What |
|---|---|
| `src/generate_data.py` | Creates the synthetic master data and messy distributor files |
| `src/` (later modules) | Profiling, cleansing, matching, validation, loading |
